# Radial electric field and ambipolarity

## Why $E_r$ is a solution, not an input

In an axisymmetric (or quasisymmetric) field the neoclassical particle fluxes are
intrinsically ambipolar: $\sum_s Z_s\Gamma_s = 0$ for any $E_r$. In a general stellarator
field they are not. The ion and electron fluxes depend on $E_r$ separately, and a steady
state requires the radial current to vanish:

$$
J_r(E_r) = \sum_s Z_s\,\Gamma_s(E_r) = 0 .
$$

The radial field evolves as $\partial_t E_r \propto -J_r$, so a root is stable when
$dJ_r/dE_r > 0$ (Helander, Rep. Prog. Phys. 77, 087001, 2014). The typical stellarator
curve has up to three roots: an ion root ($E_r < 0$, stable), an electron root
($E_r > 0$, stable) and an unstable root between them. Experimental comparisons for W7-X
are in Pablant et al. (2018, 2020).

$E_r$ enters the drift-kinetic operator through the $E\times B$ drift and, with full
trajectories, the $\dot\xi$ and $\dot x$ terms ({doc}`drift_kinetic_equation`), and the
drive through $d\hat\Phi/d\hat\psi$ ({doc}`drives_and_rhs_modes`). One evaluation of
$J_r$ is one kinetic solve. The normalized field and its SI value are related in
{doc}`normalizations`.

## Root finding from a namelist

`dkx.er` provides three entry points on the namelist route:

`radial_current(problem, er)`
: One solve at a given field, returning $J_r$, the per-species `particleFlux_vm_psiHat`
  and the solve state. The root of $\sum_s Z_s\Gamma_s$ does not depend on the radial
  coordinate because the $\hat\psi \to \hat r$ factor is positive and species-independent.

`find_ambipolar_er(...)`
: The bracket-expanding Brent method of SFINCS v3 `ambipolarSolver.F90`
  (`ambipolarSolveOption = 2`). It evaluates the bracket ends, widens the bracket until
  $J_r$ changes sign, then refines with the `zbrent` update. Two tolerances are separate:
  `current_tol` bounds $|J_r|$ (normalized) and `field_tol` bounds the bracket width
  (defaults $10^{-10}$ each); a narrow bracket without an acceptable current is rejected.
  With `all_roots=True` (default) the bracket is also scanned on `n_scan = 9` points and
  each sign change is refined, so several roots can be returned. Warm starts and Krylov
  recycling carry across evaluations.

`ambipolar_er(...)`
: The differentiable root. The forward root is a secant iteration wrapped in
  `solvax.implicit.root_solve`, so gradients follow the implicit-function theorem,

  $$
  \frac{dE_r}{dp} = -\left(\frac{\partial J_r}{\partial E_r}\right)^{-1}\frac{\partial J_r}{\partial p},
  $$

  with both Jacobians from automatic differentiation of `radial_current`
  ({doc}`../numerics/differentiation`).

Each accepted root is classified from the sign of $E_r$ and the central-difference slope
$dJ_r/dE_r$ (`dkx.er._classify`):

| Slope | $E_r$ | Label |
| --- | --- | --- |
| $> 0$ | $< 0$ | `ion` |
| $> 0$ | $> 0$ | `electron` |
| $< 0$ | any | `unstable` |
| $= 0$ | any | `marginal` |
| not finite | any | `unknown` |

A finite scan can miss tangent roots and closely spaced pairs. A small nonzero slope is
not a stability proof; it needs a resolution and uncertainty study.

## Ambipolar profiles from a native case

A native case with `run.workflow = "ambipolar_profile"` and
`electric_field.mode = "ambipolar"` solves each listed surface in physical units
(`src/dkx/workflows/ambipolar_native.py`). The relevant `[electric_field]` fields and
their defaults (`src/dkx/config.py`) are:

| Field | Default | Meaning |
| --- | --- | --- |
| `search_kV_m` | required for ambipolar runs (the template uses `[-40, 40]`) | Field interval searched on every surface |
| `search_points` | 9 | Points of the coarse uniform scan |
| `find_all_roots` | true | Refine every sign change, not only one |
| `root_tolerance_kV_m` | $10^{-3}$ | Bisection stopping width |
| `max_root_iterations` | 20 | Bisection cap |
| `continue_branches` | true | Select roots by following a branch across surfaces |
| `search_strategy` | `uniform` | `uniform` or `seeded_brackets` |
| `seed_brackets_kV_m` | none | Per-surface brackets for `seeded_brackets` |

The procedure per surface:

1. One batched coarse scan of $J_r$ over `search_kV_m` (`dkx.batch.batched_er_scan`).
2. Each sign-changing interval is refined by bracketed bisection. Every reported root is
   a kinetic solve at that field, not an interpolated point.
3. Roots are classified `ion`, `electron` or `unstable` from $E_r$ and the slope.

Across surfaces, roots are linked into branches (`continue_ambipolar_branches`) by linear
prediction from each branch's last two points and a minimum-cost assignment; a match is
admitted only within one quarter of the search span. The result records discrete branch
events: `boundary_origin`, `creation`, `loss`, `merger`, `crossing` and
`classification_transition`. These are evidence from discrete surfaces, not a resolved
bifurcation analysis.

The selected root on the first surface is the one nearest $E_r = 0$. On later surfaces,
with `continue_branches = true`, the code keeps the selected branch if it continues and
otherwise takes the root nearest the field selected on the adjacent inner surface. The reason is stored per
surface (`selection_reason`, for example `continued_selected_branch` or
`selected_branch_lost_nearest_root`), and every root, not only the selected one, is kept
in the result (`ambipolar_root_*`, `ambipolar_branch_event_*`; see
{doc}`../user_guide/outputs`). If no sign change is found the surface reports the sample
closest to zero current with reason `no_bracket_closest_sample`.

With `search_strategy = "seeded_brackets"` only the given intervals are searched, so the
result does not exclude crossings outside them.

The native route uses DKES trajectories ({doc}`index`). Ion and electron root positions
depend on the trajectory model at low collisionality (Landreman et al. 2014), so a native
ambipolar result is a DKES-trajectory result.
