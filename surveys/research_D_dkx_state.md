## Q1 Linear-solve routes and preconditioners  [ANSWERED]

Routes (module docstring, src/dkx/solve.py:1-79; case-file names structured_direct / recycled_krylov / sparse_direct_referee map to code names block_tridiagonal / gmres / direct at src/dkx/execution.py:450-452 and are the admissible `[solver] method` values at src/dkx/config.py:1247):

1. **Structured block-tridiagonal direct** (`method="block_tridiagonal"`, "tier1" in code): `solvax.direct.block_thomas_factor/solve` vmapped over the n_species*n_x independent (species,x) subsystems, rank-one border absorbed exactly (solve.py:12-26). Two kernels: full-band `build_tier1_solver` (solve.py:961) and the memory-lean truncated kernel `_solve_tier1_truncated` (solve.py:1567) that keeps only the lowest `tier1_keep_lowest=3` Legendre blocks exactly (default constant `_TIER1_KEEP_LOWEST_DEFAULT = 3`, solve.py:166) plus a "generated full" recovery `_solve_generated_full` (solve.py:1401).
   - Admissibility: `tier1_available` (solve.py:645-671) = `KineticOperator._check_block_extraction_supported()` (src/dkx/drift_kinetic.py:1769-1799) which refuses Er xiDot/xDot (L±2 coupling, :1770-1774), tangential magnetic drifts (:1781-1787), Fokker-Planck / fp_phi1 / improved-Sugama collisions (:1788-1795), external-Phi1-in-kinetic (:1796-1801); plus constraintScheme must be 0 or 2 (solve.py:664-668) and not (constraintScheme=2 with point_at_x0) (solve.py:669-670). Full-band additionally needs uniform Nxi_for_x (`_uniform_nxi_for_x`, solve.py:674-676); ramped decks go to the truncated kernel.
2. **Recycled Krylov** (`method="gmres"`, "tier2"): matrix-free `solvax.krylov.gcrot` FGMRES+recycling on `KineticOperator.apply`, right-preconditioned (solve.py:28-40). `_solve_tier2` at solve.py:2025. Admissible for everything (pinned system `(A M + I - M) x = rhs` for truncated DOFs, solve.py:2538-2548). `recycle_dim>=1` is mandatory (solve.py:2043-2054); plain restarted FGMRES is not reachable.
3. **Sparse direct** (`method="direct"`, "tier3"): materializes the operator into CSR via vmapped unit vectors (`materialize_csr`, solve.py:1029), hands to `solvax.native.splu_solve`/SuperLU on host; non-differentiable, non-jittable, guarded by `max_dense_size=8192` (solve.py:42-48, 2482). `_solve_tier3` at solve.py:1249.
4. There is no separate dense LU route in `solve()`; `materialize_dense` (solve.py:1059) exists as a helper only.

`method="auto"` decision (`_auto_route`, solve.py:2294-2366; RHS-free twin `_auto_route_structural`, solve.py:2233-2262):
 - not tier1_available -> "gmres" (solve.py:2255-2256, 2306-2308)
 - uniform Nxi_for_x and `tier1_peak_memory_bytes(op) <= budget` (default 8 GB, `_TIER1_BUDGET_GB_DEFAULT`, solve.py:154; env `DKX_TIER1_MEMORY_BUDGET_GB`, :155) -> "block_tridiagonal" (solve.py:2258-2259, 2315-2323)
 - else if truncation supported and RHS confined to lowest `keep` blocks (or RHSMode in 1/2/3 when traced) -> "block_tridiagonal_truncated" (solve.py:2325-2349)
 - else -> "gmres" (solve.py:2351-2366).
 - Under auto, a Krylov breach of `max_restarts` (default 200, solve.py:2481) escalates via `_escalate_after_tier2_stall` (solve.py:1072-1248): ladder = tried preconditioner -> "sparse" -> "multigrid" (solve.py:1141) -> widened restarts -> sparse direct only if `total_size <= max_dense_size` (solve.py:1211-1216).

Krylov preconditioners: `_TIER2_PRECONDITIONERS = ("coarse", "multigrid", "sparse", "none")` (solve.py:196). Dispatcher `build_tier2_preconditioner` (solve.py:1997-2022). Default is `preconditioner=None` + `use_preconditioner=True` -> "coarse" (`_resolve_preconditioner`, solve.py:1977-1994; defaults at solve.py:2476-2477).

**Physics-based PC that uses the exact PAS block-tridiagonal solve: YES, it exists and is the default.** `build_coarse_preconditioner` (src/dkx/coarse_precond.py:916-965) "Mirrors the Fortran preconditionerOptions defaults": collisions become self-species and x-diagonal (SFINCS preconditioner_species=1, preconditioner_x=1; FP `op.fp`/Sugama `op.sugama` reduced to PAS-like L-diagonal, coarse_precond.py:923-928, 985-990), Er L±2 xDot/xiDot and tangential magnetic-drift L±2 terms dropped (= Fortran preconditioner_xi=1 applied unconditionally, coarse_precond.py:928-929); the L-diagonal half of the magnetic drifts is kept (coarse_precond.py:991-997, citing 5838->2163 GCROT iterations on W7-X). The result is block-tridiagonal in L, uncoupled over (species,x), inverted exactly by batched block-Thomas; bordered constraint rows eliminated exactly with `solvax.operators.schur_projected_precond` (coarse_precond.py:933-936). Phi1-aware (generalized bordered Schur, coarse_precond.py:938-947). Three storage policies routed by measured size: dense bands / reusable Schur-LU-only factors (`block_thomas_factor_fn(store_offdiagonals=False)`) / checkpointed one-shot (`block_thomas_checkpointed_fn`) (coarse_precond.py:15-38, `_coarse_bands_fit` :233, `_coarse_factors_fit` :276). Three regularization pins are mandatory: 1e-8 diagonal floor, identity rows on truncated (x,l) pairs, rank-one l=0 pin (coarse_precond.py:41-48, `_coarse_subsystem_block_fn` :694). `drop_l_coupling` (sever L±1) is a separate, much stronger and measured-bad cut (6000 vs 19 iterations, coarse_precond.py:930-932). Fortran correspondence stated: preconditioner.F90 + PETSc Pmat (coarse_precond.py:50-52).

- **multigrid.py** (1901 lines): `build_multigrid_preconditioner` (multigrid.py:1461) replaces the exact block-Thomas inverse of the *same* simplified operator with a semicoarsened geometric multigrid V-cycle over (theta, zeta[, xi]) only; x and species are never coarsened (multigrid.py:16-37). xi p-coarsening (spectral truncation) is measured unsafe and off by default (multigrid.py:63-80). **Opt-in, not default**: solve.py:2575-2582 says on the NCSX full-FP ladder it "does not reach the Krylov tolerance ... so it stays opt-in". Reached only via `solve(preconditioner="multigrid")` or rung 2 of the stall ladder (solve.py:1141). Also holds a pitch-collocation surrogate study (`PitchCollocationSurrogate`, multigrid.py:1695; `pitch_collocation_surrogate` :1754) and smoothing-factor diagnostics (`measure_smoothing_factor` :1521, `line_smoother_spectral_radius` :1867).
- **sparse_precond.py** (446 lines): `build_sparse_preconditioner` (sparse_precond.py:403) assembles the same simplified operator in CSR per (species,x) subsystem and factors on host with SuperLU via `jax.pure_callback` (sparse_precond.py:20-29); exact, same map as "coarse" to round-off; l=0 pin applied by Sherman-Morrison (sparse_precond.py:48-52). Opt-in and refuses under jit/vmap/grad of operator leaves (sparse_precond.py:40-42). This is the closest analog of SFINCS's MUMPS-factored Pmat.
- **coarse_precond.py** also owns the truncated-chain helpers `_truncated_coefficients/_truncated_blocks/_truncated_params/_truncated_block_fn` (coarse_precond.py:435-556) imported by solve.py (solve.py:120-127).

Conclusion for Q1: the SFINCS-style simplified-operator preconditioner already exists (coarse_precond.py:916) and is the default for every deck that leaves the PAS/DKES family. No insertion point is needed for "does a PC exist"; the natural insertion points for a *new* PC variant are `build_tier2_preconditioner` (solve.py:1997) for dispatch, `_TIER2_PRECONDITIONERS` (solve.py:196) for the name, and `_strip_for_coarse`/`_coarse_subsystem_block_fn` (coarse_precond.py:741, :694) for a different simplification (e.g. a Fortran-faithful `preconditioner_xi=0` that keeps L±2, or `preconditioner_x=0` keeping x coupling, which would break the block-tridiagonal-in-L structure and so needs a different inner inverse).

## Q2 Krylov recycling  [ANSWERED]

Strategies present:
- **GCROT subspace recycling (fifo)** — the only strategy used by the production `dkx.solve` route. Both `gcrot(...)` call sites in `_solve_tier2` (src/dkx/solve.py:2141-2151 differentiable branch; :2186-2197 plain branch) pass `recycle=warm/recycle`, `k=recycle_dim`, `m=restart` and **do not pass `recycle_strategy`**, so solvax's default `recycle_strategy="fifo"` applies (installed solvax 0.20.0 signature: `gcrot(matvec, b, *, x0=None, precond=None, m=30, k=10, rtol=1e-8, atol=0.0, max_restarts=50, recycle=None, recycle_strategy='fifo')`; solvax docstring: "fifo" deflates slowly-converging eigenmodes only indirectly, "harmonic" = GCRO-DR deflated restarting (Parks et al. 2006), needs k <= m).
- **Harmonic-Ritz / GCRO-DR recycling** — exists only in the research-lane pitch-collocation solver `solve_collocation` (src/dkx/collocation.py:1050-1109; `recycle_strategy="harmonic"` at collocation.py:1095), preconditioned by its own multigrid. Not reachable from `dkx.solve.solve`, `run`, or the Er workflows.
- **x0 warm start** — `solve(x0=...)` (solve.py:2471) is honoured only on the non-differentiable Krylov branch (solve.py:2189); the differentiable branch deliberately takes no x0 because `custom_linear_solve` reuses the same solver for tangent RHS (solve.py:2119-2125). Structured direct ignores it.
- **Preconditioner reuse** — `SolveResult.precond` returns the `(precond, precond_t)` pair (solve.py:2221-2226; field doc solve.py:346-352, field :363) and `solve(precond=...)` feeds it back as `prebuilt_precond` (solve.py:2489, 2797); `_solve_tier2` uses it verbatim without any structural validity check (solve.py:2060-2066: "build once and hand the pair in ... 39% on the Sugama collisionOperator=3 deck"). The escalation ladder deliberately does not pass a prebuilt pair (solve.py:2057-2059).
- **Recycle pair semantics**: "right-hand-side independent — a deflation subspace, with A U recomputed and re-orthonormalized against the current operator on entry — so it is still threaded across columns" (solve.py:2122-2125); the adjoint solve always cold-starts (solve.py:2176-2178).

All Krylov machinery is imported from SOLVAX: `from solvax.krylov import gcrot` (solve.py:97; collocation.py:1073); DKX implements no Krylov method itself. Implicit differentiation wrapper: `from solvax.implicit import linear_solve` (solve.py:96).

Where threading happens in DKX:
- Er evaluations: `ErSolveState(x, recycle, result, precond)` (src/dkx/er.py:154-175); `evaluate_er`-style solve at er.py:459-473 passes `x0=x0, recycle=recycle, precond=precond` and stores `result.recycle`/`result.precond`; the bracket/root driver threads `prev.x/recycle/precond` when `warm_start=True` (er.py:659, 726-732). The differentiable branch (er.py:448-455) uses no warm start at all.
- Phi1 Newton: GCROT pair threaded across Newton iterations when `warm_start` (src/dkx/phi1.py:15-17, 199, 223, 353-357; default `gmres_recycle_dim=16`).
- Batched scans (`dkx.batch`) do not thread recycle state (only mention batch.py:216); `workflows/scans.py` and `scan.py` have no recycle/warm/precond handling.

Validity gates found: `recycle_dim >= 1` (solve.py:2043-2054); `x0.shape == rhs.shape` (solve.py:2082-2088); the ErSolveState docstring states the reused preconditioner "remains an approximate inverse for subsequent operators; original-residual and observable checks still govern acceptance" (er.py:165-170) — i.e. acceptance is by residual, not by a structural gate on the reused precond. No "harmonic"/"prepared"/"reuse" gate keywords exist in solve.py other than those described; `grep -n "recycle_strategy"` finds only collocation.py:1095.

## Q3 Differentiation of the ambipolar Er root and of linear solves  [ANSWERED]

**Er root: implicit function theorem, not unrolled.** `ambipolar_er` (src/dkx/er.py:909-1037) defines `residual(er) = radial_current(problem, er, differentiable=True)` (er.py:986-994) and wraps a value-only secant `solver(f, x_init)` (jax.lax.while_loop, er.py:996-1020) in `solvax.implicit.root_solve` = `jax.lax.custom_root` (er.py:927-932, 1037): "dEr/dp = -(dJr/dEr)^{-1} dJr/dp, with dJr/dEr and dJr/dp from autodiff of radial_current — no finite differences" (er.py:930-934). The secant iterations themselves are not differentiated (er.py:997: "Value-only secant iterations; one field JVP checks final acceptance. custom_root supplies the implicit-function-theorem parameter tangent"). The same pattern is used for the Phi1 Newton state (src/dkx/phi1.py:409-426, `solvax.implicit.root_solve`).

Admission checks that gate a returned Er derivative (added by #184 commits f4ca710/1303ba4, refined by #188 c5523fd):
- Static controls validated before preparation (er.py:967-975): `root_tol` finite & >0 (default 1e-11), `current_tol` finite & >=0 (default 1e-12), `min_abs_slope` >=0 (default 0), `max_root_iter` positive int (default 60) (signature er.py:909-923).
- Runtime acceptance callback (`jax.debug.callback`, er.py:1020-1034): finite root/current/slope, `abs(Jr) <= current_tol`, `abs(dJr/dEr) > min_abs_slope`, `abs(Jr/(dJr/dEr)) <= root_tol`; otherwise RuntimeError "Ambipolar root acceptance failed" (er.py:1026-1031). Slope comes from one `jax.jvp(f, (x_root,), (1,))` (er.py:1019). Documented as local checks that "do not establish uniqueness or grid convergence" (er.py:960-962; docs/differentiability.rst:78-146).
- Kinetic-state admission per current evaluation: the differentiable `radial_current` branch (er.py:448-455) solves with `tier1_keep_lowest=op.n_xi` (all Legendre blocks retained, er.py:451) and calls `_check_kinetic_solution` (er.py:615-648): finite x, `||A x - b|| <= tol*||b||` on the *original* operator (not the solver flag), homogeneous RHS requires entrywise zero defect (er.py:625-631); traced path uses `lax.cond` + callback (er.py:641-648). The host (non-differentiable) root path re-certifies via `_check_host_kinetic_state` (er.py:607-612) before "root acceptance/reuse".
- Every differentiable linear solve additionally records/enforces adjoint residuals (below).

**Linear solves: implicit differentiation via SOLVAX, with three distinct policies.**
- Recycled Krylov (`_solve_tier2`, solve.py:2110-2185): `_implicit_solve` (solve.py:1301-1329) = `solvax.implicit.linear_solve(matvec, rhs, solver, transpose_matvec=matvec_t, has_aux=True)` — one GCROT forward solve inside the wrapper, adjoint = cold-start GCROT on `matvec_t` (from `jax.linear_transpose` of `op.apply`, coarse_precond.py:109-118) with `precond_t` (solve.py:2171-2178). No x0 in the differentiable branch (solve.py:2119-2125).
- Full-band structured direct (`_solve_tier1`, solve.py:1475-1556): same `_implicit_solve`, forward and transpose reuse the block-Thomas factors (`t1_solver.solve(r, transpose=...)`), plus `solvax.refine.iterative_refinement` (1 sweep, `_TIER1_REFINEMENT_SWEEPS`, solve.py:160) and `_guarded_solve` on both directions (solve.py:1522-1527).
- Truncated structured direct: with `differentiable=True` and `keep == op.n_xi` the solve enters `_solve_generated_full` (solve.py:2761-2769 routing; body solve.py:1401-1474) — implicit `solvax` linear solve whose forward/transpose reuse retained generated Schur-LU factors (`_build_generated_full_solver`, solve.py:1336-1398; `block_thomas_factor_fn(..., store_offdiagonals=False)`, `GeneratedBlockTridiagFactors`) when the storage estimate fits `tier1_memory_budget_gb`, else the transpose is the JAX pullback of the generated RHS map (docs/differentiability.rst, #188 additions). With `keep < op.n_xi` (partial recovery) the derivative is the *reduced-system* derivative — taped by default, or solvax's structure-preserving `jax.custom_vjp` when `tier1_adjoint_window=w` (solve.py:2626-2648, reverse-mode only; `jax.jvp/jacfwd` raise TypeError). Partial recovery "remains outside the implicit-adjoint wrapper" and "has no full-equation adjoint admission" (docs/differentiability.rst #188 text; solve.py truncated docstring lines ~1612-1632).
- Sparse direct refuses AD (`RuntimeError`, solve.py:2826-2829).

Adjoint admission gate (#188 c161afa/f294c1c): `_residual_guard`/`_guarded_solve` (solve.py:494-643) recompute the true residual `||A^T y - g||` (never the Krylov internal estimate), require `res <= adjoint_residual_factor * max(atol, tol*||b||)` with `adjoint_residual_factor` default 1 (`DEFAULT_ADJOINT_RESIDUAL_FACTOR = 1.0`, solve.py:461; param solve.py:2475, doc 2540-2547), record a diagnostic backward-error floor that "never widens this gate" (solve.py:535-547), require zero defect for homogeneous equations, and raise at execution time from `jax.debug.callback` unless `check_adjoint=False` (default `True`, solve.py:2474). Records live in `SolveResult.adjoint` (`AdjointDiagnostics`, solve.py:246-309), bounded to the latest record per equation/RHS column.

Evidence tests: tests/test_er.py:339 (`test_ambipolar_er_grad_matches_finite_difference`), :381 (routed current gradient vs cold solves), :495/:517 (rejects inaccurate cancelling fluxes; current adjoint vs packed original equation), :656-711 (acceptance under jit/grad/vmap; rejects invalid roots); tests/test_native_execution_result.py:178 (`test_native_profile_gradient_matches_independently_rebuilt_ambipolar_roots`, with quadratic Taylor remainders per docs) and :319; tests/test_solve.py:420-536 (generated-full adjoint corruption rejection, budget respect, padding cannot relax tolerance), :1136-1223 (singular tier2 adjoint raises; flagship FP cs1 must meet tolerance; guard survives jit), :1619-1700 (bounded adjoint vs taped; reverse-mode only).

## Q5 Prepared execution (#173, #174, #186, #187)  [ANSWERED]

- **`KineticOperator` is a registered JAX pytree with a static pitch layout (#173, commit 6396c2f).** `n_xi_for_x` is folded into the pytree aux data as a hashable tuple (src/dkx/drift_kinetic.py tree_flatten: "Pitch truncation defines the discrete layout and solver route. Keep it hashable and static; physical coefficients remain dynamic leaves"); docs/api.rst (added by #173): discrete dimensions, model switches and `n_xi_for_x` are static compilation keys; "A change to active pitch layout requires a new trace even when the rectangular state shape is unchanged. Same-layout operators with changed coefficients can reuse an executable"; and explicitly: "Replacing only `n_hat` or `t_hat` on an existing operator does not rebuild its collision coefficients. Compilation reuse is distinct from valid physical-data or preconditioner reuse; it does not establish a prepared restart contract or make the namelist/geometry builders differentiable."
- **`dkx.er.prepare(deck)` -> `ErProblem`** (src/dkx/er.py:291-343): base operator built once at reference Er=1 so ExB/Er term flags are on; `operator_at_er` (er.py:267-286) overrides only `dphi_hat_dpsi_hat` and `dphi_hat_dpsi_hat_kinetic` = `dphi_per_er * Er` via `dataclasses.replace` — exact because those terms are linear in the drive, differentiable in Er, no rebuild. Requires RHSMode=1 (er.py:308-312). `ErProblem` fields: operator, dphi_per_er, z_s, er_initial/min/max, solve_method, tol, er_units, `_profile_builder` (er.py:179-210).
- **`dkx.prepare_er_scan(case, surface_index, differentiable_profiles, quadrature_order=128)`** (src/dkx/api.py:580-627; #182 83f1652, #187): prepares one native `Case` surface without a solve; keeps the case's `[solver]` method/tolerance (`_route_name`, api.py:622); accepts Er in kV/m; with `differentiable_profiles=True` builds `op` with `build_collisions=False` and attaches `_prepare_profile_builder` (src/dkx/execution.py; skips duplicate collision assembly, #187 46702e9). Docstring caveat: "This does not enable factor reuse or differentiate geometry/Case parsing" (api.py:595).
- **`ErProblem.with_profiles(density_m3=, temperature_keV=)`** (er.py:212-223): arrays shaped (n_surfaces, n_species); returns a new `ErProblem` whose operator has refreshed `n_hat`, `t_hat`, `dn_hat_dpsi_hat`, `dt_hat_dpsi_hat` (3-point native radial stencil, execution.py `_prepare_profile_builder`) and fresh collisions (PAS: `make_pitch_angle_scattering_v3_operator` analytic; full-FP: `prepare_fokker_planck_v3_profiles(...)(density, temperature).at_uniform_density(density, n_xi)`). Usable inside jit/grad/vmap (docs/differentiability.rst:338-380). Fixed: geometry, surface locations, masses/charges, Coulomb logarithm, solver policy, field bounds, layout (differentiability.rst:348-351). Raises ValueError if `differentiable_profiles` was not set (er.py:220-221).
- **`prepare_fokker_planck_v3_profiles(...)`** (src/dkx/collisions.py:1123-1200+; #186 c73e1b6): returns `build(n_hats, t_hats)` -> `FokkerPlanckV3Phi1Operator`; densities and temperatures vary independently under JIT/AD; Rosenbluth integrals via composite Gauss-Legendre with static `quadrature_order` per panel (default 128) instead of the host QUADPACK parity builder (collisions.py:1130-1141); layout, masses, charges, nu_n/Coulomb log, grids fixed; requires positive speed nodes (no x=0); "does not update kinetic profiles/drives or certify reusable factors".
- **`FokkerPlanckV3Phi1Operator.rescale_temperature(scale)`** (collisions.py:1024-1046; #186 fff6520): exact fixed-grid update for a *common* scalar temperature factor — kernels `k_nu,k_cd,k_ce,k_rosen` scale as `scale**-1.5`; JIT/AD-safe; independent per-species temperature changes still need a full rebuild (collisions.py:1033); caller must also update kinetic operator temperatures/drives.
- **`at_uniform_density(n_hats, n_xi)`** (collisions.py:1048-1060+; #174 1b2f98d): refresh uniform FP coefficients from stored unit-density kernels; differentiable in density at fixed temperatures.

What varies under JIT/AD without rebuild: Er (via `operator_at_er`), n/T profiles and their radial drives (via `with_profiles`), FP collision coefficients in density (`at_uniform_density`) and in a common temperature scale (`rescale_temperature`) or independently in (n,T) via the quadrature builder; batch leaves in `dkx.batch` (any non-discretization `KineticOperator` leaf, batch.py:78-97).
What cannot: pitch layout `n_xi_for_x` and any grid/derivative matrix (static compile keys / `_DISCRETIZATION_FIELDS`); geometry and Case/namelist parsing (host-only, not differentiable: api.py:594, api.rst #173 text); Coulomb logarithm/nu_n; per-species independent T in `rescale_temperature`; factor/preconditioner reuse is *not* certified by any prepared object (er.py:219-220 "reuse factors separately only after checking their validity"; docs/differentiability.rst:378-380 "do not certify factor reuse or a complete geometry/profile/ambipolar optimization chain"). Retained generated Schur factors (#188) "belong to this operator and solve execution; this is not yet a serialized restart or a cache across changing profile/geometry inputs" (docs/differentiability.rst #188 text).
